### `bytesLt` (def)

Bytewise lexicographic order on byte strings (R2), as in LevelDB/RocksDB. Compare the first byte where the strings differ, as an unsigned number. If one string is a proper prefix of the other, the shorter one is smaller. So "a" < "ab" < "b".


### `scan_complete` (theorem)

A scan leaves out an in-range pair only when the limit was reached and that pair's key is larger than every key returned. So the scan returns the *first* `limit` pairs in range (R7).

*Status:* Proven

```lean
theorem scan_complete {s : Store} (hs : s.WellFormed) (lo : Bytes) (hi : Upper Bytes)
    (limit : Nat) {k v : Bytes} (hkv : s.lookup k = some v) (hlo : bytesLt k lo = false)
    (hhi : hi.admits k = true) (hout : (k, v) ∉ s.scan lo hi limit) :
    (s.scan lo hi limit).length = limit ∧
      ∀ p ∈ s.scan lo hi limit, bytesLt p.1 k = true
```

```lean
    ∃ h rs, ((Impl.session (m := FsM) cmds).run (startState c0 [])).1 = .ok (h, rs) ∧
      repliesMatch rs (runFrom s0 (cmds.map (Cmd.map toBytes))).2 = true ∧
      h.index.toList = (runFrom s0 (cmds.map (Cmd.map toBytes))).1 ∧
      h.index.height ≤ 3 * Nat.log2 (h.index.size + 1) + 2
```

### `store_crash_consistent` (theorem)

Crash consistency (R10, R11). Run a session on a healthy log with any I/O faults, then crash in any allowed way. - **If open fails,** it reports an I/O error and the log still stands for the same state. - **Otherwise,** the replies match the reference up to some command j. From j on, every reply is an I/O error, so the store blocks itself after a failure. After the crash, the log stands for the reference state after the first j commands (every acknowledged write survives), or after the first j+1 (the write in flight was applied in full).

*Status:* **Obligation** — about an implementation hole; proven in Stage 4

```lean
theorem store_crash_consistent {c0 : Bytes} {s0 : Store} (hs0 : logState c0 = some s0)
    (cmds : List (Cmd ByteArray)) (φ : List Fault) (ch : CrashChoice) :
    let scmds := cmds.map (Cmd.map toBytes)
    let out := (Impl.session (m := FsM) cmds).run (startState c0 φ)
    let c1 := crashOutcome out.2.disk ch
    match out.1 with
    | .error r => r.isIOError = true ∧ logState c1 = some s0
    | .ok (_, rs) => ∃ j ≤ cmds.length,
        rs.length = cmds.length ∧
        repliesMatch (rs.take j) ((runFrom s0 scmds).2.take j) = true ∧
        (∀ r ∈ rs.drop j, r.isIOError = true) ∧
        (logState c1 = some (runFrom s0 (scmds.take j)).1 ∨
          (j < cmds.length ∧ logState c1 = some (runFrom s0 (scmds.take (j + 1))).1))
```

### `store_refuses_corrupt` (theorem)

Refusing a corrupt log (R12). If the log is corrupt at offset p, the session fails with `ERR CORRUPT p` (or with an I/O error, if reading fails), and the log is left exactly as it was.

*Status:* **Obligation** — about an implementation hole; proven in Stage 4

```lean
theorem store_refuses_corrupt {c0 : Bytes} {p : Nat} (hc : recover c0 = .corrupt p)
    (cmds : List (Cmd ByteArray)) (φ : List Fault) :
    let out := (Impl.session (m := FsM) cmds).run (startState c0 φ)
    (out.1 = .error (.corrupt p) ∨ ∃ d, out.1 = .error (.ioError d)) ∧
      out.2.disk = ⟨c0, c0⟩
```

### `storeCheck_spec` (theorem)

`check` never modifies the log (R21), and it reports the reference recovery outcome.

*Status:* **Obligation** — about an implementation hole; proven in Stage 4

```lean
theorem storeCheck_spec (st : FsState) :
    ((storeCheck (m := FsM)).run st).2.disk = st.disk ∧
      (((storeCheck (m := FsM)).run st).1.isIOError = true ∨
        ((storeCheck (m := FsM)).run st).1.map toBytes =
          match recover st.disk.content with
          | .ok bs n t => .log bs.length n t
          | .corrupt p => .corrupt p)
```
